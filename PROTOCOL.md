# Протокол сборки — v7 (текущая)

> Финалов больше не существует. Есть текущая версия и место второго исполнителя.

## Что это

Протокол «верификации через исполнение»: положения сборки считаются не написанными,
а исполненными. Главный артефакт — `compendium_run.py`: 12 прогонов, в каждом двое
независимых исполнителей (два разных кодовых пути), среды чистые и дефектные.

## История

| Шаг | Что сделано | Исход |
|---|---|---|
| Проходы 1–5 | сборка протокола (П1–П4, ЗАПЛАТ-6) | «сухой остаток» |
| Ревью коллег | 5 файлов — все чтением, ни одного запуска | 0 найденных дефектов |
| Проход 6 | чинка П3: «МОЖЕТ сменить» вместо «сменил — жди» | чинил до прогона |
| Сжатие | «сухой остаток» вернул опровергнутую форму П3 | регрессия внесена текстом |
| Прогон 1-го исполнителя | 12 прогонов по протоколу | 3 дефекта, невидимых в 5 файлах ревью |
| **Проход 7 (текущий)** | патчи 1–4, перепрогон 12 случаев | ПАЛО 0 |

## Положения

- **П1.** Хранится последовательность, не сущность.
- **П2.** Последовательность + условия → выход. Гарантия — в пределах условий.
- **П3 (верная форма, патч 1).** Смена шагов МОЖЕТ сменить выход. Тот же выход при
  изменённых шагах — не норма и не опровержение, а повод: эквивалентность
  последовательностей доказывается или отмечается явно.
- **П4.** Несовпадение → проверять по порядку: условия → исполнение → реализация →
  ожидание. Ожидание — последним, но проверяемо. Порядок оправдан зависимостью рамок,
  не вероятностью (EMERGENT.md, п. 4).

## Критерий v7 (патчи 2 и 4)

ВЕРИФИЦИРОВАНО = предусловия выполнены и сверяемы ∧ двое независимых исполнителей
с нуля сошлись ∧ сходство сверено с критерием выхода.

Три измерения (сходство × предусловия × сверка) дают 8 классов; v6 различала 2,
v7 реализует 6:

| Вердикт | Смысл |
|---|---|
| ВЕРИФИЦИРОВАНО | предусловия ∧ сходство ∧ сверка пройдена |
| ПУСТО | сходство есть, предусловия нарушены — сходство вне условий ничего не верифицирует |
| НЕСВЕРЯЕМО | сходство есть, сверка с критерием невозможна (закрытое наблюдение) |
| UNKNOWN | не сошлись без вины (предел точности прибора ниже чувствительности системы) |
| ДЕФЕКТ → ЗАПЛАТ-6 | не сошлись по вине исполнителя |
| СОГЛАСОВАНО-НЕВЕРНО → ЗАПЛАТ-6 | сошлись, но не на том: расхождение с ожиданием (патч 4) |

## ЗАПЛАТ-6

расхождение → условия → исполнение → реализация → ожидание → исправить.
Прогон подтверждает оба корня: в условиях (шаг 2) и в ожидании (шаг 5).

## ЗАПЛАТЫ/

Непроверяемая запись до первой чужой сборки. Запись, не знавшая чужого прогона,
не имеет права притязать на статус решения — она просит его (EMERGENT.md, п. 5).

## Правила поведения

1. Регрессии вносятся сжатием и пересказом: пересказ обязан проходить тот же прогон
   (12 случаев) до того, как заменит оригинал (EMERGENT.md, п. 8).
2. Не объявлять финалов.
3. «Пёс — сбоку»: место шутки = место, где протокол рискует объявить себя эталоном.
   Если в сборке нет ни одного места, где можно посмеяться над ней самой, сборка уже
   эталон из себя (EMERGENT.md, п. 7).

## Механизм

Текст протокола исполняется механизмом, а не только глазами:

- **Конечный автомат** (`protocol_fsm.py`): вердикты v7 — состояния; П4/ЗАПЛАТ-6 —
  контур РАСХОЖДЕНИЕ → УСЛОВИЯ → ИСПОЛНЕНИЕ → РЕАЛИЗАЦИЯ → ОЖИДАНИЕ → ИСПРАВИТЬ →
  ПРОВЕРКА. Таблица переходов запрещает: перескок через рамку, переход минуя прогон,
  выход из терминального вердикта, возврат к прогону без найденного корня.
  Self-тест: 13 векторов (12 случаев прогона + вектор вины), 2 контура, 6 незаконных
  переходов пойманы, все 6 вердиктов достижимы — достижимость из фактических
  результатов, не из ожиданий.
- **CI** (`.github/workflows/protocol.yml`): на каждый пуш и PR исполняет 12 случаев
  и self-тест автомата. Переиспользуемый workflow: подключение к любому репозиторию —
  `uses: rtynbirf/assembly-protocol/.github/workflows/protocol.yml@main`.
- **Страж роя** (`fleet_sweep.py` + `.github/workflows/fleet-sweep.yml`): инвариант I-2
  как автомат. Обходит живые тела, исполняет self-тест автомата на раннере, проверяет
  проводку и последний прогон каждого тела. Вердикты: PASS / GATED-LEGAL (ворота
  платформы, тело в legit_open_states) / PENDING (транзиент по v7; stuck >60 мин —
  тревога) / FAIL (провал вне легитимных состояний = красный CI). Ежедневный cron +
  dispatch; срез — `fleet/FLEET_VERDICT.csv` (EMERGENT.md, п. 9).

## Роли и верификация

- **Первый исполнитель** — прогон выполнен: `RUN_LOG.txt` (12 случаев, v6 против v7).
- **Второй исполнитель** — место свободно. Твой ход: `python3 compendium_run.py`.
  Ломай на своих средах. Судья — ручной: вывод скрипта — демонстрация, не самопроверка.

Счёт прогона (v7): ВЕРИФИЦИРОВАНО 6, ПУСТО 2, UNKNOWN 1, НЕСВЕРЯЕМО 1,
ПРОТОКОЛ ЛОВИТ 1, СОГЛАСОВАНО-НЕВЕРНО 1. v6 тем же счётом: «верифицировано»
11 из 12 — в том числе у пустых, несверяемых и согласованных с неверным ожиданием.
